# 实验验证

[合成数据](../practice/end-to-end.md)可用于验证数学计算和数组操作。硬件验证还需要已知距离、速度、方向或位移的目标，分别检查采集格式、坐标换算和校准误差。

## 1. 记录采集条件

至少保存 ADC 的复数/实数模式、位宽和字节序，LVDS 排列，启用的接收通道，以及 profile、chirp、frame 三类设置。它们分别规定扫频与采样参数、每次发射启用的 TX、每帧的循环和时序。在 SDK CLI 中常对应 `profileCfg`、`chirpCfg`、`frameCfg`；使用 mmWave Studio 时保存其实际配置文件或脚本，不要求使用相同的命令名称。天线坐标与板卡型号也应一起记录。

这些信息分别决定 I/Q 怎样配、数组怎样排、距离与速度怎样换算、角度该用哪组阵元。某一项缺失时，应明确是哪一步还不能确认。

## 2. 距离与数据排列

在已知距离放一个强反射器，例如 1 m、2.5 m、5 m；测量距离时说明参考点。按实际采集配置核对 I/Q 配对、接收通道和 TX 顺序，再观察主峰是否随目标位置移动，误差是否近似恒定，周期重复结构是否仍然出现。

每个位置重复采集，记录均值和标准差。只在一个位置碰巧出现峰，无法验证整个距离换算。

## 3. 速度与符号

先看静止反射器是否接近零 Doppler，再使用径向速度已知的移动装置。对同一份频谱分别套用 160 µs 与 480 µs 横轴，检查哪个与实际采集顺序及参考速度相符。还要确认靠近、远离对应哪一侧，并测试速度超过无模糊范围后的混叠。

## 4. 通道与角度

列出每个虚拟通道对应的 TX、RX 和物理位置。用已知方向反射器估计通道复增益，扣除该方向的理论几何相位，再校正数据。用没有参与校准的其他角度验证误差，而不是只在校准位置检查。

移动目标还需比较 TX 时间补偿前后的角度；否则静止目标测角正确，不代表移动目标也正确。

## 5. 微位移

用位移台或振动器提供已知幅度和频率，先确定稳定距离格与通道，再比较估计位移与参考位移。记录信号幅度下降、相位失锁、目标跨距离格的时刻。需要去趋势或滤波时，保存处理前后曲线，并说明可能去掉了哪些真实低频运动。

帧周期为 80 ms 时，每帧取一点的采样率为 12.5 Hz。估计低于 1 Hz 的变化需要记录多个运动周期；插值不延长真实观测时间。

## 6. 偏差与均方根误差

令估计值与参考值之差为 $e_i=\widehat x_i-x_i$，则偏差与均方根误差分别为：

\[
\mathrm{bias}=\frac1N\sum_i e_i,\qquad
\mathrm{RMSE}=\sqrt{\frac1N\sum_i e_i^2}.
\]

$N$ 为有效测量次数。bias 保留误差正负，反映整体偏高或偏低；RMSE 先平方再平均，因此正负误差不会相互抵消。例如两次距离误差为 $+1$ cm 和 $-1$ cm，bias 为 0，RMSE 为 $\sqrt{(1^2+(-1)^2)/2}=1$ cm。

Python：

```python
error = np.asarray(estimated) - np.asarray(reference)
bias = np.mean(error)
rmse = np.sqrt(np.mean(error**2))
```

MATLAB：

```matlab
error = estimated(:) - reference(:);
bias = mean(error);
rmse = sqrt(mean(error.^2));
```

两列数据要先按相同目标、相同时间对应，并统一单位。误差很小时，还要考虑参考仪器本身的不确定度；报告重复次数与误差分布，不只给一个最好的数。

## 7. 原程序的修正顺序

先让解析模式真正控制处理分支，再验证配置与数据排列；接着修复所有通道的 Doppler 和慢时间间隔；然后完成阵列映射、幅相校准与运动补偿；最后加入目标选择、跨帧关联和可靠相位处理。每完成一步，就保留一份配置、中间数组和验证结果。

`project/src/` 保留原处理算法，对应现有诊断图；教学实现位于 `docs/wiki/examples/`。后续修正原程序时应另存结果，并与旧版使用同一输入比较。
