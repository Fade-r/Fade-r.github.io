    参数、单位与 shape 账本¶

    每帧到底有多少数据¶

    设每 chirp 有 (N_s=256) 个 ADC samples，每帧有 (N_c=128) 个 loop，3 个 TX、4 个 RX，每个复数含 I/Q 两个 int16：

    \[ N_{\mathrm{int16/frame}} =N_sN_cN_{\mathrm{TX}}N_{\mathrm{RX}}\times2 =256\times128\times3\times4\times2 =786432. \]

    本次文件含 78,643,200 int16，因此：

    \[ N_{\mathrm{frames}}=78643200/786432=100. \]

    文件大小与 metadata 一致

    shape 变化¶

    raw int16 / frame             [786432]
complex stream / frame        [393216]
MATLAB logical frame          [256, 128, 12]
Python canonical adc_cube     [100, 12, 128, 256]
                                frame, VC, loop, sample
range_profile                 [256, 128, 12]
speed_profile                 [256, 128, 12]
angle_profile                 [256, 128, 180]

    读代码时先写 shape

    NumPy 的 axis=0/1/2 只有结合 [sample, loop, virtual_channel] 才分别具有 Range、Doppler、Angle 的物理意义。

    当前参数与派生量¶

    参数 值 单位 进入的计算
    Fs 10 MHz beat-frequency / range bin
    Ns 256 sample/chirp range FFT 长度
    Nc 128 loop/frame Doppler FFT 长度
    S 29.982 THz/s beat frequency 与有效带宽
    Tr 60 µs 完整 ramp 带宽
    idle_time 100 µs Tc = 160 µs
    Tframe 80 ms 跨帧采样时刻
    fc 约 77.90 GHz 波长
    λ 约 3.851 mm 速度与位移尺度

    实验与实测的区别

    交互标记使用当前项目参数计算理论坐标。它用于理解公式，不代表本次数据中确实存在所设定的目标。

    自检：为什么 angle FFT 的 180 点不写进每帧原始样本数？

    因为 180 是后处理零填充后的空间 FFT 长度，不是采集到的独立阵元数，也不增加原始文件字节数。
