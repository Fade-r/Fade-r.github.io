    从采集开始：雷达怎样把回波存进文件¶

    先把完整路线看清楚。雷达芯片负责发射、接收、混频和 ADC 采样；DCA1000 把高速采样数据送到电脑；MATLAB 或 Python 再把文件变成可解释的数组。

    1. 发射并接收回波

      扫频信号碰到物体后反射回来。回波的延迟和相位里包含距离与运动信息。

    2. 混频，得到 I/Q 基带信号

      回波与本机信号比较，得到较低的差频。ADC 采的是这个基带信号，而不是直接以 77 GHz 采样。

    3. ADC 采样，经 LVDS 输出

      每次扫频获得一组数字采样。I、Q、RX 和 TX 的排列由芯片接口和本次采集配置决定。

    4. DCA1000 经网线传到电脑

      电脑接收数据包并保存文件。包顺序、丢包和补零记录会影响之后的数据解释。

    5. 整理为 ADC 文件，再离线处理

      确认文件中是否还有包头，按格式读出整数，配 I/Q，然后进入距离、速度、方向和相位分析。

    1. 采集前先写下你要观察什么¶

    测距离，需要足够的有效扫频带宽；测速度，需要合适的同通道重复间隔；测低频微动，需要足够长的连续记录。这三个要求会影响不同的参数，不能只找一个“分辨率”数值。

    参数 改变了什么 后面在哪一步用
    斜率 S、ADC 采样率 Fs、点数 Ns 采样覆盖的带宽与可表示拍频 距离换算
    扫频时间、空闲时间、TX 顺序 同一通道重复观测的间隔 速度换算、运动补偿
    每帧轮次 一帧中的观察时长 速度格间距
    帧周期、帧数 跨帧采样时刻与总记录时长 微位移和低频谱
    RX/TX 启用与板卡天线位置 通道数量和空间采样位置 数组排列、测角

    本文后续先使用项目设置讲解计算。真正重新采集时，应从你实际写入设备的配置中取值。

    2. 在采集软件里完成哪些动作¶

    按匹配板卡的 mmWave Studio/SDK 版本连接和初始化雷达，配置接收通道、ADC 模式和 LVDS；设置 profile、每个 chirp 启用的 TX，以及 frame 的轮次与周期。然后配置 DCA1000 和主机接收，先让采集端准备好，再触发雷达帧，等待记录结束并保存配置与日志。

    不同版本的界面和命令可能不同，但这组依赖关系不变：接收端已准备 → 雷达开始发射 → 数据包接收完成 → 检查采集记录。硬件连线、供电与开关设置按对应开发板和 DCA1000 用户手册操作；本文的 MATLAB/Python 代码从已保存的数据开始，不包含板卡控制驱动。

    IWR1443 与 IWR1843 在采集入口的区别¶

    两种芯片都有 3 TX、4 RX，支持的 LVDS 数据通道数却不同：IWR1443 为 4，IWR1843 为 2。因此，采集接口配置和文件解析要与实际设备匹配；两块板的天线位置也应分别查表。FFT 的数学计算可以共用。

    3. 文件保存后，先检查体积¶

    用容易心算的小例子：每次扫频 100 个点，4 个 RX，单 TX，每帧 10 次扫频，I/Q 各占 2 字节。每帧就是 100 × 4 × 10 × 4 = 16000 字节。采 20 帧，应为 320000 字节。这个计算能快速发现少帧、混入额外数据或配置记错。

    本项目三路轮发、256 点、128 轮、100 帧的期望长度检查如下。

    Python：

    from pathlib import Path
ns, loops, tx, rx, frames = 256, 128, 3, 4, 100
expected = ns * loops * tx * rx * 4 * frames
actual = Path('project/data/raw/adc_data.bin').stat().st_size
assert actual == expected
print(actual)  # 157286400 字节

    MATLAB：

    ns = 256; loops = 128; tx = 3; rx = 4; frames = 100;
expected = ns*loops*tx*rx*4*frames;
info = dir('project/data/raw/adc_data.bin');
assert(isscalar(info) && info.bytes == expected);
disp(info.bytes); % 157286400 字节

    这里假设文件只含这些通道的 16 位复数 ADC 负载。某些格式会保留未启用 lane 的零填充，或加入其他数据段，届时要按实际格式重新算。体积正确也不能排除丢包后补零，因为补零会保持长度。

    4. 区分网络接收文件和纯 ADC 文件¶

    SWRA581B 第 9 节描述的 mmWave Studio 流程会先生成 adc_data_RAW_0.bin，再经过数据包重排、缺失补零、元数据移除，得到 adc_data.bin。版本和采集方式不同，处理工具也可能不同。先确认你拿到的是哪个阶段的文件，不要对已经整理好的文件重复去头，也不要把未整理的数据直接配 I/Q。

    本项目保留的是 adc_data.bin，尚未归档完整采集日志。接下来先从复数与采样理解 I/Q；已经熟悉时可直接进入文件解析。
